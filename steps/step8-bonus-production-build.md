# 심화 - 프로덕션 빌드

## 문제 상황

지금까지는 개발 환경에서 Vite의 `middlewareMode`를 사용해 서버를 실행하고 있다. 하지만 실제 배포 환경에서는 Vite 개발 서버를 띄울 수 없다.

> **생각해보기:** 개발 환경과 프로덕션 환경에서 서버 코드 실행 방식은 어떻게 달라야 할까? 클라이언트 코드와 서버 코드를 각각 빌드해야 하는 이유는 무엇일까? 빌드된 정적 파일(JS, CSS)의 경로는 어떻게 알 수 있을까?

## 목표

클라이언트와 서버 빌드를 분리하여 프로덕션 환경에서 동작하는 SSR 서버를 구성한다.

> [!IMPORTANT]
> 먼저 스스로 고민해본 뒤, 막히면 하나씩 열어보세요.

<details>
<summary>힌트 1: 클라이언트와 서버 빌드는 왜 따로 해야 할까?</summary>

클라이언트 빌드는 브라우저용 번들(JS, CSS, 이미지)을 생성하고, 서버 빌드는 Node.js에서 실행할 서버 엔트리를 번들링한다. 대상 환경이 다르기 때문에 빌드 설정도 달라야 한다. Vite는 `vite build`와 `vite build --ssr`로 이를 구분한다.

</details>

<details>
<summary>힌트 2: 빌드된 에셋 경로는 어떻게 참조할까?</summary>

클라이언트 빌드 시 Vite가 매니페스트 파일을 생성한다. 이 파일에는 각 소스 파일이 빌드 후 어떤 경로로 변환되었는지가 기록되어 있다. 서버는 이 매니페스트를 읽어 올바른 JS/CSS 파일 경로를 HTML에 삽입한다.

</details>

<details>
<summary>힌트 3: 프로덕션 서버는 개발 서버와 뭐가 다를까?</summary>

프로덕션에서는 Vite 미들웨어 대신, 빌드된 정적 파일을 직접 서빙해야 한다. `express.static`으로 클라이언트 빌드 결과물을 서빙하고, 서버 엔트리는 빌드된 파일을 `import`하여 사용한다.

</details>

## 완료 기준

- 클라이언트 빌드와 서버 빌드가 각각 성공한다.
- 빌드된 결과물로 서버를 실행하여 SSR이 정상 동작한다.
- Vite 개발 서버 없이 프로덕션 모드로 서버가 실행된다.

## 스스로 확인해보기

- 개발 환경에서 `vite.ssrLoadModule`을 쓰는 것과 프로덕션에서 빌드된 모듈을 `import`하는 것의 차이는 무엇인가?
- 매니페스트 파일이 없다면 프로덕션에서 어떤 문제가 생기는가?
- 빌드 시 환경 변수(`NODE_ENV`)는 어떤 영향을 미치는가?

## 키워드

- `vite build --ssr`
- 클라이언트/서버 빌드 분리
- 매니페스트 파일을 통한 에셋 경로 참조
